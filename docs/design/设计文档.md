# 1 引言

## 1.1 编写目的

本文档描述「隐私计算联邦学习软件原型」（以下简称原型）的概要设计与详细设计，交付中国移动江西公司作为研发过程资料。文档回答三个问题：原型由哪些部分组成、每个功能在工程上怎样实现、合同中的每一条验收项由原型的哪些功能承担并怎样验证。

预期读者是甲方技术评审人员、项目开发与测试人员。第 3 章按功能模块展开技术实现，第 4 章按合同条目（C-01 至 C-16、T-01 至 T-03）逐条给出实现方式与验证方法，评审时可以直接按合同编号查阅。

## 1.2 项目背景

稀土上下游的价格、库存与交易数据分散在多个参与方手中，各方不能把原始数据交给对方或第三方，但联合建模又需要使用这些数据。本项目以氧化钕（Nd₂O₃）、氧化铈（CeO₂）、氧化镧（La₂O₃）的历史价格时序数据为主要场景，研究在数据不出域的前提下完成联合训练的技术，合同约定交付 1 套集成隐私求交、同态加密、差分隐私、联邦学习的软件原型。

合同对原型提出两类要求：功能清单 16 项（C-01 至 C-16），技术参数指标 3 项（T-01 至 T-03），其中 T-01 要求梯度重构攻击成功率不高于 5%、单轮平均通信压缩比不低于 6，T-02 要求联邦训练相对集中式明文训练的 Accuracy 下降不超过 3%。

## 1.3 范围

原型覆盖五个业务模块：联邦学习、同态加密、多方安全计算、隐私求交、差分隐私。验收依据两份文件：合同附件《成果形式及验收要求》，以及甲方提供的《自研功能清单 V5》。两者合并为 72 个带固定编号的三级功能，其中 V5 清单 60 个，合同有而 V5 没有的补充项 12 个。各模块的三级功能数量如下。

## 1.4 术语与缩略语

| 术语 | 含义 |
|---|---|
| 联邦学习（FL） | 各参与方在本地数据上训练，只交换模型更新，由聚合方合成全局模型 |
| FedAvg | 联邦平均算法，各方上传完整模型更新，聚合方按样本数加权平均；本文用作通信量对照基线 |
| 参与方 / 训练节点 | 持有本地数据并执行本地训练的节点，角色值 trainer |
| 聚合节点 | 接收各方更新并合成全局模型的节点，角色值 aggregator |
| 同态加密（HE） | 允许在密文上直接做加法或乘法，解密结果等于明文运算结果的加密方式 |
| Paillier | 半同态加密方案，支持密文加密文、密文乘明文，只处理整数 |
| CKKS | 近似同态加密方案，支持浮点数向量的加法与乘法，结果带有可控的近似误差 |
| BGV / TFHE | 另外两种全同态方案，BGV 做整数精确运算，TFHE 做逐比特可编程自举运算 |
| 多方安全计算（MPC） | 多方在互不泄露输入的前提下共同计算函数结果 |
| 秘密共享（SS） | 把一个值拆成若干份额分给各方，单方份额不含信息，足够多份额才能还原 |
| 混淆电路（GC） | 姚氏协议，把函数表示为布尔电路并加密求值，适合比较与逻辑运算 |
| 不经意传输（OT） | 发送方持有多个值，接收方只取其中一个，发送方不知道取了哪个 |
| 隐私求交（PSI） | 两方在不暴露非交集元素的前提下求出共同元素 |
| ECDH-PSI / KKRT / 非平衡 PSI | 三种求交协议：基于椭圆曲线 Diffie-Hellman、基于 OT 扩展、适用于两方数据量悬殊的场景 |
| 差分隐私（DP） | 通过加噪使单条记录是否存在于数据集中对输出的影响受 ε、δ 约束 |
| ε、δ | 隐私预算参数，ε 越小隐私越强；δ 为允许失败的概率 |
| RDP | Rényi 差分隐私，一种更紧的隐私预算累计方法 |
| Top-k 稀疏化 | 每轮只上传绝对值最大的 k 个梯度分量，其余留在本地累积 |
| 误差反馈 | 把未上传的梯度残差累加到下一轮，避免稀疏化造成的偏差 |
| DLG / iDLG | 两种梯度重构攻击，由截获的梯度反推出原始训练样本；iDLG 先解析出标签再还原输入 |
| MSE / RMSE / MAE | 均方误差、均方根误差、平均绝对误差 |
| SSE | Server-Sent Events，服务端向浏览器单向推送事件的 HTTP 机制 |
| KMS | 密钥管理服务，私钥只以引用形式出现在平台中 |
| 隐语（SecretFlow） | 开源隐私计算框架，本项目差分隐私模块基于其原生 DP 能力封装 |

# 2 总体设计

## 2.1 系统定位

原型是一个平台控制台加一组后端服务。控制台面向项目管理员和各参与方的操作人员，用来创建联邦项目、配置算法与隐私策略、启动与监控任务、查看评估结果；后端服务承担训练编排、密码学计算、预算记账和指标评估。原型不是单个算法程序，而是把五项隐私计算能力放在同一个项目与任务模型下，让一次联合训练可以组合使用求交、加密聚合和差分隐私。

## 2.2 总体架构

原型分为五层，上层只通过接口调用下层。

| 层次 | 组成 | 职责 |
|---|---|---|
| 展示层 | 平台控制台（浏览器单页应用），五个业务模块共 14 个二级页面 | 表单与校验提示、任务状态与曲线展示、SSE 事件消费 |
| 接口层 | REST 接口（JSON，统一响应包）与 SSE 推送 | 鉴权、参数校验、错误码、项目作用域隔离 |
| 业务服务层 | 项目与节点服务、算法与模型服务、训练编排服务、聚合与安全策略服务、评估服务、PSI 流水线服务、MPC 任务服务、DP 策略与记账服务、HE 密钥服务 | 业务规则、状态机、元数据持久化 |
| 计算引擎层 | 联邦学习框架（集成逻辑回归、XGBoost、神经网络、时序模型与稀疏化聚合）、同态加密库、秘密共享与混淆电路与 OT 协议库、PSI 协议库、隐语差分隐私模块 | 实际的训练与密码学计算 |
| 基础设施层 | 元数据库、模型与数据集制品存储、密钥管理服务（KMS）、日志与审计存储、参与方节点本地数据目录 | 持久化与密钥托管，原始数据只存在于参与方节点本地目录 |

一次完整联合训练的数据流如下。

1. 两个参与方各自登记数据集，平台只保存元数据与 schema。
2. PSI 流水线对两方的求交键做安全求交，得到对齐样本的索引，不暴露交集之外的任何元素。
3. 特征对齐后，训练任务按项目配置创建，并携带聚合策略（秘密共享或同态加密）、稀疏化参数和 DP 配置。
4. 每轮训练中，各参与方在本地训练，对更新依次做裁剪、加噪、Top-k 稀疏与量化，再按聚合策略以份额或密文形式上传。
5. 聚合节点只能看到聚合所需的份额或密文，合成全局模型后下发；每轮的指标、通信量、隐私预算与加解密耗时写入存储。
6. 控制台通过 SSE 接收每轮事件，并可随时对任务执行暂停、恢复、终止。

## 2.3 部署架构

验收环境的拓扑固定为服务端 1 台、参与方客户端 3 个，外加平台控制台。

| 部署单元 | 数量 | 运行内容 | 说明 |
|---|---|---|---|
| 服务端 | 1 台 | 平台后端服务、聚合节点（角色 aggregator）、密钥服务入口、评估引擎、元数据库 | 对应合同 T-01 所述「单服务端」 |
| 参与方客户端 | 3 个（参与方 A、B、C） | 训练节点（角色 trainer），本地数据目录，本地训练进程或容器 | 每个节点登记独立 data_dir，只访问自己的目录 |
| 平台控制台 | 1 套 | 静态页面，由 Web 服务器托管 | 浏览器访问，通过 HTTPS 调用服务端接口 |

节点的标识沿用 node-* 形式的节点 ID，一个项目内节点 ID 唯一。节点信息包括 IP、端口、角色、数据分区标识和本地数据目录，由任务编排页管理。训练任务启动时，服务端为每个节点分配一个训练进程或容器，任务终止时释放。

## 2.4 技术选型及理由

| 方面 | 选型 | 理由 |
|---|---|---|
| 控制台 | 原生 JavaScript 单页应用，无构建步骤 | 静态文件即可部署，不依赖打包工具链；页面与接口一一对应，便于评审逐页核对 |
| 接口风格 | REST + JSON，统一响应包，长任务用 SSE | 接口文档（API.md）已定稿，前端与后端可以并行开发；SSE 比轮询省请求，且只需单向推送 |
| 联邦学习引擎 | FATE 类联邦学习框架，本项目算法集成其中；逻辑回归与树模型分别对应秘密共享逻辑回归和 SecureBoost，神经网络与时序模型基于 PyTorch 配合 FedAvg 聚合 | 复用框架成熟的调度、通信与容错能力，把工作量集中在稀疏化聚合与隐私增强上 |
| 隐私求交与安全计算 | 使用框架自带的 ECDH-PSI、KKRT、秘密共享、混淆电路、OT 能力，包装成独立功能 | 协议实现经过社区验证，自行实现密码学原语的风险高于收益 |
| 差分隐私 | 基于隐语（SecretFlow）原生 DP 模块封装，平台只依赖 5 个统一接口，另保留 Opacus、TF-Privacy 两种可替换实现 | 隐语提供联邦场景下的梯度加噪与安全聚合；统一接口保证实现可替换 |
| 同态加密 | Paillier 用 python-paillier；CKKS 与 BGV 用 SEAL 或 TenSEAL、Pyfhel、OpenFHE；TFHE 用 TFHE-rs | 覆盖半同态与全同态，底层库可在界面切换 |
| 持久化 | 关系型元数据库保存项目、节点、任务、指标、策略；制品存储保存模型文件与数据集文件；私钥由 KMS 托管 | 元数据与制品分离，原始数据不入平台库 |
| 鉴权 | Bearer token，请求头 Authorization | 接口文档统一约定，401 对应业务码 40100 |

## 2.5 前后端契约与 mock 机制

前后端以 API.md 及 docs/api 下各模块文档为唯一契约。控制台里的页面代码只通过 Api.get、Api.post、Api.patch、Api.put、Api.del、Api.upload、Api.download、Api.subscribe 这组请求函数访问接口，不直接读取任何后端内部数据。

后端未就绪时由浏览器内的 mock 服务响应同一组接口，mock 路由写在 web/js/mock 下，每个模块一个文件，通过 MockServer.extend 挂到内核。切换到真实后端只需修改 web/js/config.js 中的两项配置：apiBase 指向后端地址，useMock 置为 false。请求路径、请求体和响应解析在两种模式下完全一致，页面代码不需要改动。

mock 的数值遵循两条规则：同输入同输出，随机种子取项目、任务或配置的哈希值，因此结果可复现；数值要有可解释的来源，例如通信量按公式计算，加解密耗时按底层库的公开基准折算。这些规则使 mock 既能支撑前端验收，也能作为后端实现的对照样例。技术指标相关页面的数值来自原型内置评估引擎的仿真结果，本文在 4.17 至 4.19 逐处说明。

所有契约测试放在 web/tests 下，用 Node 自带的 node:test 运行，无外部依赖。每个测试名以三级功能编号开头，例如 [FL-ORCH-01]，验收进度表据此汇总每个编号的测试结果。

# 3 功能设计

本章按五个模块、14 个二级功能展开。每个二级功能依次说明功能说明、处理流程、关键算法与参数、接口、异常与校验规则。括号中的编号是该内容对应的三级功能。接口路径中花括号表示路径参数，错误码含义见 6.2。

## 3.1 联邦学习模块

### 3.1.1 任务编排

#### 功能说明

任务编排以项目为单位管理联邦学习：创建项目并设定基准模型、聚合轮数和训练目标，维护参与方节点，保证各节点数据隔离，管理内置算法、注册算法、自定义模型及其版本，提供参数模板（FL-ORCH-01 至 FL-ORCH-09，对应合同 C-01、C-02）。

#### 处理流程

1. 创建项目：校验名称、轮数、训练目标后，写项目主表与配置表；选择带演示数据时，先登记演示节点，再播种演示数据集与任务。
2. 维护节点：添加节点时校验 IP、端口、节点 ID，并发起连通性检查；通过后写入节点表。
3. 选择算法：从算法目录中选内置算法，或注册新算法，或上传自定义模型；自定义模型先经结构校验才登记。
4. 新建训练任务：以项目配置为默认值，叠加所选算法的参数（可用模板回填），写入任务并记录算法引用（算法名、版本、模板 ID）。
5. 导出配置：把项目、训练配置、节点清单与隔离策略导出为 JSON。

#### 关键算法与参数

项目配置。项目主表保存 project_id、name、type；配置表 fl_project_config 保存 description、base_algorithm 与 model_version、total_rounds、target_metric 与 target_value、revision。训练目标的比较方向由指标决定：loss、rmse、mae 要求不大于目标值，accuracy、auc 要求不小于目标值。目标指标所属的任务类型必须被基准模型支持，模型版本必须存在于算法版本表。聚合轮数取 1 至 200 的整数。

节点。节点表主键为 (project_id, node_id)，字段有 ip、port、role（trainer 或 aggregator）、data_partition、data_dir、last_heartbeat_at。node_id 只允许小写字母、数字和短横线，项目内唯一。

数据隔离。每个训练节点登记独立的数据目录，默认形如 /data/fl/{项目}/{分区}，策略为目录权限 0700 加节点挂载命名空间隔离。访问判定规则是发起访问的节点等于目录属主才放行，越权访问写入审计表 fl_isolation_audit，并记录操作人。跨节点通信只允许 ModelUpdate 消息的白名单字段：训练节点上传 weights_delta、num_samples、local_metrics，聚合节点下发 global_weights 与 round。传输审计取任务最后一轮各节点的消息，字节数来自训练引擎每轮记录的 upload_kb，梯度元素数按 float32 的 4 字节换算，并把消息字段名与本项目所有数据集的列名逐一比对，命中即判为泄露。

内置算法。内置算法登记在 fl_algorithm（kind 为 builtin）：逻辑回归 FedLogisticRegression（对应隐语 SS-LR）、XGBoost FedXGBoost（对应 SecureBoost）、神经网络基类 FedNeuralNet 及子类 FedMLP、FedCNN1D、时序模型 FedLSTM 与 FedTCN（基类 FedSequenceModel，PyTorch 加 FedAvg）。所有算法继承 FedEstimator，并暴露同名的三个方法：fit(X, y, *, rounds, aggregator, params) 返回 TrainReport，predict(X) 返回 ndarray，evaluate(X, y) 返回指标字典。分类算法输入形状为 [样本数, 特征数]，评估返回 loss 与 accuracy；时序算法输入形状为 [样本数, 窗口长度, 特征数]，评估返回 rmse 与 mae。每个算法带 JSON Schema 参数定义，训练引擎据此校验并补默认值。

算法注册与版本。注册信息写 fl_algorithm（名称、任务类型、基类、模型格式 pkl、pt、h5 或 onnx）和 fl_algorithm_version（版本号、params_schema、制品 file_id）。版本号格式为主.次.修订。参数 schema 采用 JSON Schema 子集：根节点 type 为 object，参数 type 限 integer、number、string、boolean，约束限 minimum、maximum、enum、default、required，并检查 minimum 不大于 maximum、enum 与类型一致、默认值满足约束。fl_algorithm.current_version 是当前版本指针，每次发布与回滚写入 fl_algorithm_op_log（action、from_version、to_version、operator、reason、at）。同名再注册即发布新版本，版本号必须递增；自定义模型同名再次上传自动把次版本号加 1。回滚只移动指针，不删除任何版本；新建任务取当前版本的 schema 与制品，并把版本号写入任务的 algo_ref，已创建的任务不受回滚影响。

自定义模型校验。前端先以 multipart 调 POST /files（purpose 为 fl_model）上传，再以 file_id 调用模型登记接口做结构校验。校验依次检查扩展名、文件大小、文件头与反序列化：pickle 检查 STOP 操作码，PyTorch 检查 ZIP 中央目录，HDF5 检查文件签名与 model_config，ONNX 检查 graph.node；随后检查层结构与输入形状是否匹配任务类型。通过的模型以 kind 为 custom、项目作用域登记，用 CustomModelWrapper 统一包装 fit、predict、evaluate 三个方法，并给出层数、参数量和输入形状。

参数模板。模板存 fl_param_template（algo_id、name、params、preset 标记、创建人），name 在同一算法内唯一。每个内置算法至少有 2 套预置模板，例如 XGBoost 默认模板为 max_depth 6、eta 0.3、n_estimators 200、subsample 0.8，快速基线为 4、0.5、100，高精度为 8、0.05、800。保存模板与新建任务共用同一个 schema 校验器，并补齐默认值。平台预置模板不可删除，自定义模板可以删除。

### 3.1.2 过程管控

#### 功能说明

过程管控负责训练任务的全生命周期：状态机、启动前检查、暂停与恢复、强制终止，以及训练过程中的指标存储、收敛曲线、剩余时间预估和历史指标导出（FL-PROC-01 至 FL-PROC-08，对应合同 C-03、C-04）。

#### 处理流程

1. 启动：任务处于 Created、Terminated 或 Failed 时可启动。服务端先做三项预检（项目配置、节点可用性、算法兼容性），全部通过才迁移到 Running，并为每个节点分配一个训练容器。
2. 运行：聚合循环逐轮执行，每轮聚合后计算并存储全局与各节点的指标，通过 SSE 推送 round_completed 事件。
3. 暂停：中断聚合循环，保存当前轮次的断点（轮次、检查点路径、全局模型摘要、聚合器优化器状态、各节点数据游标），容器置为 suspended。
4. 恢复：从断点轮次继续，轮次既不重复也不丢失。
5. 终止：向训练进程发送 SIGKILL，释放容器与资源，状态迁移到 Terminated。
6. 结束：全部轮次完成后迁移到 Success；节点心跳丢失等异常迁移到 Failed，并记录失败原因。

#### 关键算法与参数

状态机。任务有六种状态：Created、Running、Paused、Success、Failed、Terminated。允许的迁移如下表，不在表内的动作返回 40901，响应中带 allowed_actions 供界面禁用按钮。每次迁移追加一条 state_history 记录，含 from、to、action、operator、reason、at，自动迁移（跑满轮次、心跳丢失）的操作人记为训练引擎，因此六种状态的可达性可以由历史记录核对。节点心跳丢失由节点的在线标志触发：节点管理接口把某节点置为离线后，使用该节点的 Running 任务迁移到 Failed，failure_reason 写明节点与轮次。

| 当前状态 | 动作 | 目标状态 |
|---|---|---|
| Created | start | Running |
| Running | pause | Paused |
| Running | terminate | Terminated |
| Running | 全部轮次完成 | Success |
| Running | 节点心跳丢失等异常 | Failed |
| Paused | resume | Running |
| Paused | terminate | Terminated |
| Terminated、Failed | start | Running（从第 0 轮重开） |
| 非 Running 的任意状态 | reset | Created |

启动预检。start 与 resume 执行前做三项检查。项目配置：任务所属项目及其配置存在，否则 40400。节点可用性：参与节点仍在项目中（已被移除返回 40901，data.missing_node_ids 列出）、全部在线（离线返回 42201，data.offline_node_ids 列出）、在册节点仍满足至少 2 个训练节点加 1 个聚合节点（不足返回 40000）。算法兼容性：算法在任务类型的可选列表内，自定义模型的制品文件存在，注册算法支持该任务类型，不满足返回 40000。预检失败不改变任务状态，通过后响应带逐项结果 preflight。资源分配：为每个参与节点分配一个训练容器（镜像 registry.local/fl-runtime:1.2.0，训练节点 4 核 8 GB，聚合节点 2 核 4 GB），容器 ID、进程号与启动时间记入 runtime.workers。

断点。暂停时保存的检查点路径形如 /data/fl/ckpt/{job_id}/round_{轮次}.ckpt，记录当前已完成轮次、全局模型的 SHA-256 摘要与字节数、本轮全局指标、聚合器的动量与学习率调度步数、各节点的数据读取位置（epoch 与 batch_offset）。恢复前重新预检，之后从断点轮次的下一轮继续，响应的 resumed_from_round 等于暂停时的轮次，状态迁移记录写明「从第 N 轮断点继续」，曲线上的轮次连续、不重复、不丢失。强制终止仅在 Running 或 Paused 时允许：全部容器以 SIGKILL 结束并记录释放时间，节点的运行中任务数立即归零。

指标存储与曲线。每轮聚合后按任务类型写入指标：分类任务写 loss 与 accuracy，时序任务写 rmse 与 mae（对目标列做 Min-Max 归一化后计算，取值在 0 到 1 量级，不同数据集之间可比）。每条记录按 series 区分全局与各节点，并带 recorded_at，同时经 SSE 推送。曲线用 ECharts 绘制：两张折线图分别对应任务类型的两个指标，横轴为轮次，纵轴取该指标的量纲范围，可在仅全局与各节点之间切换，每收到一次推送追加一个点；聚合节点不持有训练数据，页面不画它的本地曲线，接口与 CSV 保留其记录。

剩余时间预估。以每轮聚合耗时 d 为观测值做指数滑动平均：s₁ = d₁，sᵣ = α × dᵣ + (1 − α) × sᵣ₋₁，α 取 0.3，预估剩余时间 = sᵣ × (总轮数 − 已完成轮数)，已用时间 = 各轮耗时之和，暂停期间不计时。接口同时返回朴素平均法的结果（已用时间除以已完成轮次再乘剩余轮数）作为对照，并给出 α、公式与逐轮明细，说明平滑后的预测对单轮波动不敏感。任务未开始时返回 null，Success 为 0。训练推送 round_completed 事件中的 eta_sec 与 elapsed_sec 直接采用平滑结果，页面使用推送值。

指标查询与导出。历史指标可按项目 ID、任务 ID、起止时间过滤；CSV 列固定为 project_id、job_id、task_type、round、series、loss、accuracy、rmse、mae、recorded_at，文件带 UTF-8 BOM，不适用的指标列留空。

### 3.1.3 聚合与安全

#### 功能说明

聚合与安全页为项目配置梯度聚合策略：秘密共享聚合或同态加密聚合，二者共用一套 Top-k 稀疏化与量化参数；同态模式下生成并管理聚合密钥对，公钥可查看；配置可一键恢复默认，并保存到当前联邦项目（FL-AGG-01 至 FL-AGG-07，对应合同 C-05、C-06）。

#### 处理流程

1. 页面读取项目聚合配置，返回已保存配置、平台默认值、按项目训练节点数计算的推荐值和各参数的取值范围。
2. 用户切换策略后只改变 strategy 并重绘对应的参数表单；每次输入经 220 毫秒去抖后调用估算接口，由后端校验并返回通信量估算。
3. 同态策略下生成密钥对：旧的 active 密钥置为 rotated，新密钥写入密钥表。
4. 保存时整体校验，通过后落库；任务编排页新建任务时读取 strategy 作为默认聚合方式。
5. 恢复默认时用平台默认值覆盖项目配置并落库，已生成的密钥保留。

#### 关键算法与参数

配置对象。一个项目一份配置，结构为 strategy（ss 或 he）、ss、he、sparsification 与 updated_at。

| 分组 | 字段 | 含义与约束 |
|---|---|---|
| ss | parties | 参与方数 n，2 至 16，默认取项目训练节点数 |
| ss | threshold | 门限 t，2 ≤ t ≤ n |
| ss | dropout_tolerance | 掉线容忍数 d，0 ≤ d ≤ n − t |
| ss | field_bits | 有限域位数，16 至 64，且不小于量化位数加 ceil(log₂n)，保证 n 方求和不溢出 |
| ss | mask_rotation_rounds | 掩码种子轮换周期，1 至 100 轮 |
| he（Paillier） | key_size_bits | 模数位数，2048、3072 或 4096 |
| he（Paillier） | precision_bits、batch_size | 定点精度；批打包数，须满足 批打包 × (精度 + ceil(log₂n) + 1 位符号) ≤ 密钥长度 − 1 |
| he（CKKS） | poly_modulus_degree | 多项式阶数 N，取 4096、8192、16384 或 32768 |
| he（CKKS） | coeff_modulus_bits | 系数模数总位数，不超过 128 位安全上限（N 为 4096、8192、16384、32768 时分别为 109、218、438、881），且不小于缩放因子位数加 20 |
| he（CKKS） | scale_bits、batch_size | 缩放因子 Δ = 2^scale_bits，20 至 60 位；批打包不超过 N/2 |
| sparsification | topk_ratio、quant_bits | Top-k 保留比例 ρ，0.1% 至 100%；量化位数 4、8、16 或 32 |
| sparsification | error_feedback | 是否启用误差反馈 |

推荐规则。门限取多数派 t = floor(n/2) + 1，掉线容忍取满 d = n − t，掩码种子每 10 轮轮换；Paillier 批打包取明文空间可容纳的最大值 floor((密钥长度 − 1) / (精度 + ceil(log₂n) + 1))；CKKS 取 N = 8192 的标准参数（系数模数 200 位、Δ = 2^40、4096 个槽位）。

秘密共享聚合。每个参与方对量化后的梯度加随机掩码，掩码由成对协商的种子派生，在有限域上求和时掩码相互抵消；门限 t 保证在最多 d 个参与方掉线时仍能还原聚合结果；掩码种子每 mask_rotation_rounds 轮重新协商。

同态加密聚合。参与方用聚合公钥加密本地更新，聚合节点在密文上求和，由密钥服务解密聚合结果；Paillier 对多个定点数做批打包以减少密文条数。

Top-k 稀疏化与误差反馈。采用全局 Top-k：服务端按上一轮聚合结果下发统一的下标集合，客户端只上传这 k = ceil(ρP) 个位置的量化梯度（P 为模型参数个数）。统一下标使秘密共享的掩码和同态密文的槽位自然对齐，上行不需要携带下标。未上传的残差通过误差反馈累积到下一轮。

通信量估算。FedAvg 单轮通信总量 = n × 2 × P × 32 位（上行与下行各一份 32 位浮点完整更新）。本算法单轮通信总量 = n × (上行 + 下行) + 掩码种子协商。上行 = k × 有限域位数（同态模式为 ceil(k / 批打包) × 单密文位数）；下行 = k × 32 + min(k × 18, P)，其中 18 位是下标编码开销，min 表示下标集合不会超过完整位图；种子协商 = n(n − 1) × 512 / 轮换周期（位）。验收用的 2 层 LSTM，P = 203,143。压缩比 = FedAvg 单轮平均通信总量 ÷ 本算法单轮平均通信总量。

密钥。密钥记录含 key_id、scheme、密钥参数、public_key、fingerprint（SHA-256）、private_key_ref（kms:// 引用）与 status。私钥只以 KMS 引用出现，界面与接口都不输出私钥材料。该密钥与同态加密模块共用同一套生命周期（见 3.2.2），聚合页生成的密钥以 purpose 为 fl_aggregation 写入同一张密钥表，因此任务详情、任务公钥与本页公钥的 key_id 始终一致。

### 3.1.4 技术指标验证

#### 功能说明

技术指标验证页对应合同 T-01、T-02，提供三类评估：梯度重构攻击评估（FL-EVAL-01）、通信压缩比评估（FL-EVAL-02）、联邦训练精度衰减评估（FL-EVAL-03）。评估是异步长任务，创建后后台运行，进度由 SSE 推送，结果可导出报告。

当前数值来自原型内置评估引擎的仿真结果。评估接口、判定口径与统计字段按下文设计定义。

#### 处理流程

1. 页面读取默认配置（GET .../evaluations/defaults），用户按需调整后提交评估。
2. 后端创建评估记录（status 为 running），同一项目同一类评估同时只能有一个在运行。
3. 评估引擎逐阶段推进，经 SSE 的 progress 事件推送进度与阶段名，完成时推送带完整 result 的 finished 事件。
4. 页面展示各组结果与是否达标，历史记录可按类型过滤，评估报告可导出。

#### 关键算法与参数

评估场景。数据集为 ds_{project}_ree_price，包含 Nd₂O₃、CeO₂、La₂O₃ 日度价格，Min-Max 归一化，输入窗口 30 日、9 维特征、预测步长 7 日；联邦架构为 1 个服务端加 3 个客户端；模型为 2 层 LSTM，参数 203,143 个；批大小为 1。

梯度重构攻击评估（FL-EVAL-01）。攻击者截获某客户端的上行内容。对照组截获明文 FedAvg 梯度；本算法组截获经 Top-k 稀疏、8 位量化和高斯差分隐私（ε = 8，δ = 1e-5，裁剪阈值 C = 1.0）处理后的单方梯度，并保守假设秘密共享的掩码已被去除，即按最不利情形评估。DLG 用 L-BFGS 最小化梯度匹配误差 ‖∇W(x′, y′) − ∇W‖²；iDLG 先由输出层梯度解析出标签，再只优化输入。判定口径：还原样本与原样本在 Min-Max 归一化空间逐元素 MSE 不大于 0.0025（等价于 RMSE 不大于 0.05）记为还原成功；成功率 = 还原成功数 ÷ 攻击样本数，DLG 与 iDLG 分开统计。可配置项有攻击样本数（20 至 1000，默认 200）、攻击迭代次数（50 至 2000，默认 300）、被攻击客户端和随机种子。每组给出攻击样本数、还原成功数、成功率与平均还原 MSE。

通信压缩比评估（FL-EVAL-02）。同一任务下，逐轮统计全部上下行字节。FedAvg 每轮 = 3 × 2 × P × 32 位；本算法按 3.1.3 的同一公式计算，掩码种子每 10 轮协商，保留数量按梯度能量动态调整：第 r 轮保留比例 ρ_r = ρ × (1 + 0.3 × e^−(r−1)/4 + 抖动)，前几轮保留偏多，随收敛回落。压缩比 = 两者各自对全部轮次取算术平均后相除。同时在时间上最后 20% 的测试窗口计算 RMSE 与 MAE，给出相对 FedAvg 的变化百分比，用来说明压缩没有以牺牲效果为代价。可配置轮次（5 至 100，默认 20），其余参数默认取项目已保存的稀疏化与有限域配置。

联邦训练精度衰减评估（FL-EVAL-03）。同一 CNN 结构与 SGD 超参（学习率 0.01，动量 0.9，批大小 64）。集中式明文基线合并 3 方数据训练「联邦轮次 × 本地 epoch」个 epoch，使总计算量与联邦侧一致；联邦侧为 3 个客户端，采用 Top-k 稀疏化、高斯差分隐私（ε = 8，δ = 1e-5）和秘密共享安全聚合，数据划分支持独立同分布（IID）与 Dirichlet 分布（α = 0.5）。Accuracy 在官方 10,000 张测试集上计算。下降幅度 = 集中式 Accuracy − 联邦 Accuracy，单位为百分点；同时给出相对下降百分比。

## 3.2 同态加密模块

### 3.2.1 算法管理

#### 功能说明

算法管理提供同态加密算法库：半同态 Paillier、全同态 CKKS 与 BGV（另列 TFHE），支持整型与浮点型数据，支持底层库切换、明密文编码与精度设置，并根据安全强度、乘法深度和精度需求给出参数推荐（HE-ALGO-01 至 HE-ALGO-08，对应合同 C-11、C-12、C-13）。

#### 处理流程

1. 页面读取算法目录与底层库目录，显示每种方案支持的运算。
2. 用户选择方案与底层库，保存为项目默认配置。
3. 在运算验证区输入两组数据，系统按方案执行加密、密态运算、解密，并与明文直接计算的结果比对，给出误差、耗时和密文大小。
4. 输入为浮点而方案只支持整数时，系统先按精度做定点编码，运算后再还原。
5. 参数寻优区输入安全等级、乘法深度、精度和批大小，返回推荐参数与候选对比。

#### 关键算法与参数

方案与默认参数如下。

| 方案 | 运算能力 | 默认参数 |
|---|---|---|
| Paillier | 密文加密文、密文乘明文；不支持密文乘密文 | 库为 python-paillier；模数 n 为 2048 位（按 NIST SP 800-57 约 112 位安全，可选 3072 位达到 128 位）；每个明文对应一条 4096 位密文（约 0.5 KB）；明文空间按 \|m\| < 2^2045 校验 |
| CKKS | 浮点数向量的加法与乘法，结果为近似值 | N = 8192，模数链 [60, 40, 40, 60] 位，缩放因子 Δ = 2^40，总模数 200 位，不超过 128 位安全对应的 218 位上限；向量按 4096 个槽位打包为一条密文 |
| BGV | 整数精确加法与乘法 | N = 8192，明文模数 t = 1032193（20 位批处理素数），\|m\| ≤ 516096 |
| TFHE | 逐比特可编程自举，对应 FheInt32 | 对应 TFHE-rs 与 OpenFHE BinFHE，每个数一条密文，\|m\| ≤ 2^31 − 1 |

底层库目录与各库公开能力一致：SEAL 4.1 与 TenSEAL 0.3（CKKS、BGV）、Pyfhel 3.4（CKKS、BGV）、OpenFHE 1.2（CKKS、BGV、TFHE）、TFHE-rs 0.7（TFHE）、python-paillier 1.5（Paillier）。项目默认配置为 { scheme, library, precision }，未保存时为 ckks、seal、精度 4。

定点编码。整数方案处理浮点数时，编码 encoded = round(x × 10^p)，p 为精度（小数位数，0 至 8），按十进制字符串逐位四舍五入，不经过二进制浮点，例如 1.005 在 p = 2 时编码为 101；解码为 encoded / 10^p。结果以字符串返回，避免精度丢失。加法时两个操作数同乘 10^p；乘法时各操作数独立缩放，整数操作数不放大，结果缩放因子为指数之和，解密后除回。全整数输入缩放因子为 1；CKKS 原生支持浮点，不做转换。精度每增加 1 位，误差上界缩小为原来的十分之一（误差上界 = 0.5 × 10^−p），编码位数约增加 3.3 位；同精度两数相乘时缩放因子为 10^2p，更容易溢出，接口对每档精度同时给出 overflow 与 mul_overflow 标志。

CKKS 近似误差。运算验证中，CKKS 解密值等于明文结果加确定性仿真噪声：加法噪声为 (1 + |x|) × 2^−28，乘法含重缩放噪声为 (1 + |x|) × 2^−22，因此乘法误差大于加法误差，二者都远小于 1e-4；种子取输入哈希，同输入同结果。

参数智能寻优（HE-ALGO-08）。输入为安全等级、乘法深度 d、精度（小数位数）和批大小。规则如下：缩放因子位数 = ceil(d_prec × log₂10) + 20，其中 d_prec 为精度位数，20 位是编码与重缩放噪声的余量，取值限制在 20 至 60 位；模数链为 [q0, Δ 重复乘法深度次, P]，q0 = P = min(60, Δ + 20)；N 取满足 HomomorphicEncryption.org 安全标准系数模数上限（三元秘密、经典攻击模型，128 位安全下 N = 8192 对应 218 位、N = 16384 对应 438 位，与 SEAL 的 CoeffModulus::MaxBitCount 一致）且 N/2 不小于批大小的最小值。性能估计以 SEAL 4.1 单线程、N = 8192、模数链长度 L = 3 的量级为基准（加法 0.07 毫秒，乘法含重线性化与重缩放 2.9 毫秒），按 N × L 与 N × log₂N × L × (L + 1) 外推；密文大小 = 2 × N × L × 8 字节。返回推荐值、更大的可行 N，以及小一档的不可行对照，并写明依据。

|---|---|

| GET、PUT /projects/{project_id}/he/config | 项目默认方案、库与精度 |
| POST /he/verify | 运算验证（加密、密态运算、解密、与明文比对） |

### 3.2.2 应用集成

#### 功能说明

应用集成把同态加密接入联邦学习：提供「生成密钥、加密、密态运算、解密」四步的可视化流程；在联邦任务中一键启用同态加密聚合；管理密钥的生成、分发、存储、销毁与自动轮换；在正式训练前用模拟梯度验证加解密与聚合的正确性；在日志中记录每个环节的耗时与密文大小（HE-APP-01 至 HE-APP-05，对应合同 C-14）。

#### 处理流程

1. 四步流程：生成密钥对，加密输入，在密文上运算，解密并与明文结果比对。未到的步骤按钮禁用；切换项目时销毁本次会话密钥并回到第 0 步。
2. 一键启用：对 Created、Terminated、Failed 状态的任务，把聚合方式切换为 he，并显示聚合公钥。
3. 密钥生命周期：生成后可分发到节点、轮换、销毁；自动轮换策略按项目配置。
4. 流程测试：每个参与方生成模拟梯度，经加密、聚合、解密后与明文求和比对，四项校验全部通过才判定通过。
5. 日志：测试与训练任务的每个环节展开为日志行，可筛选并导出。

#### 关键算法与参数

密钥生命周期。密钥元数据含 status、purpose、distributed_to（节点 ID 与分发时间）、rotated_from、rotated_to、rotate_reason、destroyed_at。公钥与参数存在密钥表，私钥标注为由平台 KMS 托管，不出域。轮换 = 生成同方案同参数的新密钥并继承分发节点，旧密钥保留，只用于解密历史密文；销毁会删除密钥及其下密文，并留下销毁记录。自动轮换策略为 { enabled, period_days }，周期 1 至 365 天，读取密钥列表或更新策略时检查 purpose 为 fl_aggregation 的密钥是否已满周期并自动轮换；会话密钥 24 小时过期，不参与轮换。

流程测试模拟。每个参与方生成 dim 维、服从 N(0, 0.02²) 的模拟梯度，种子取项目、方案、维度和参与方数。Paillier：逐元素 round(g × 10^p) 为整数后求和再除回，每 32 个定点数打包进 2048 位明文的 64 位槽位，10,000 维对应 313 条密文；CKKS：按 4096 个槽位打包，聚合噪声为 √参与方数 × 2^−28。与明文求和逐元素比较，得到最大与平均绝对误差。精度不足导致误差超过容差时判定未通过并说明原因，结果同时写入性能日志。

性能日志。日志有两类来源：流程测试按步骤与参与方展开；aggregation 为 he 的训练任务按已完成轮次展开为每个训练节点的加密、聚合方的密态聚合、密钥服务的解密。密文条数 = ceil(模型参数量 / 32)，例如 XGBoost 每轮上传 2,176 维（32 加 36 个特征乘 32 个分桶的梯度与 Hessian 直方图）对应 68 条，单条约 0.52 KB，每节点每轮约 35.4 KB。耗时按 Paillier 基准折算：加密 3.4 毫秒每条，聚合 0.8 毫秒每条每方，解密 4.2 毫秒每条，另加 ±6% 的确定性抖动。接口按环节汇总次数、平均耗时与密文合计，CSV 带 UTF-8 BOM，列含耗时（毫秒）与密文大小（KB）。

## 3.3 多方安全计算模块

### 3.3.1 协议管理

#### 功能说明

协议管理内置三类协议并支持基础算子组合：秘密共享（安全求积、求均值）、混淆电路（安全比较、逻辑运算）、不经意传输扩展（向量 OT）；支持 3 方及以上参与并动态配置角色；提供默认参数与高级参数；按参与方数量和数据规模预估通信量与耗时（MPC-PROTO-01 至 MPC-PROTO-07）。

#### 处理流程

1. 页面读取协议目录，选择算子并组合成 1 至 8 步的流程。
2. 配置参与方：从项目节点中选择，分配输入方、计算方、输出方角色。
3. 设置参数：默认配置或高级模式；可保存为项目参数。
4. 试运行：服务端按流程用演示数据计算，只返回份额、各步可见性和最终结果。
5. 预估：按流程、参与方数、数据行数与带宽估算通信量与耗时。
6. 创建任务：任务创建时固化预估结果，交由运维监控页跟踪。

#### 关键算法与参数

秘密共享（MPC-PROTO-01）。加法秘密共享在 Z/2^ℓ 上实现，默认环位数 ℓ = 64，定点小数位 f = 16。输入 x 编码为 round(x × 2^f) mod 2^ℓ；前 C − 1 份由以项目、参与方、行号、持有方为输入的种子哈希（FNV-1a 加线性同余）生成，最后一份补差，使全部份额之和 mod 2^ℓ 还原编码值；份额区不含任何明文。求和是本地运算，0 轮通信；求均值 = 本地求和后除以公开常数，定点截断并打开 1 次；求积采用 Beaver 三元组，每次乘法打开 2 个值。恶意敌手模型按 SPDZ 风格附加 MAC，预估中通信乘 2、计算乘 2.2。

混淆电路（MPC-PROTO-02）。采用姚氏混淆电路代价模型：b 位比较电路含 AND 门 b 个、XOR 门 3b 个；对 k 个数取最大值含 AND 门 2b(k − 1) 个、XOR 门 5b(k − 1) 个；AND 与 OR 的归约使用 m − 1 个 AND 门。每个 AND 门在半门（half-gate）优化下为 2κ 位密文（GRR3 为 3κ），XOR 门在 Free-XOR 下为 0（关闭时 3κ），安全参数 κ = 128 位；求值方的输入标签经 OT 取得，每比特 3κ。轮数为常数 4（基础 OT 3 轮加发送混淆表 1 轮）。从秘密共享切换到混淆电路时，自动计入一次份额到混淆值的转换（b 位加法电路，2 轮）。

向量 OT（MPC-PROTO-03）。向量 OT 由 m 条并行的 1-out-of-2 OT 实现不经意选取：输出方对第 i 行选真实值，其余行选零，发送方不知道 i。采用 IKNP 扩展，k 次基础公钥 OT（默认 k = 128，可配 128 至 256）扩展为 m 条 OT，每条通信 k/8 + 2 × 8 字节；基础 OT 每次按 96 字节、0.5 毫秒计。轮数 = 3（基础 OT，可离线）+ 每批 2 轮，即 3 + 2 × ceil(m / 批大小)。恶意模型增加 KOS15 一致性校验，通信乘 1.05。

算子组合（MPC-PROTO-04）。流程是 1 至 8 步的列表，每步为 { operator, protocol, operand }。服务端按顺序做类型推导：起点类型为 parties，每个算子用 io 表把输入类型映射到输出类型（例如 secure_sum 把 parties 映射为 vector，把 vector 映射为 scalar），不在表内的组合被拒绝，并逐步检查 protocol 属于 operator 支持的协议。试运行使用 4 行确定性演示数据（氧化钕月度成交价，按项目与参与方生成），计算明文参考结果，但响应只返回份额、各步可见性和最终结果，结果只对输出方公开。秘密共享步骤的结果超出 2^(ℓ−1−f) 时给出溢出警告。前端本地做同样的类型推导用于就地提示，最终以服务端校验为准。

多方与角色（MPC-PROTO-05）。参与方候选取自项目节点，按顺序编为参与方 A、B、C、D，项目节点不足 3 个时补充虚拟节点。每方的 roles 是 input、compute、output 的子集。校验规则：参与方不少于 3 个、不重复、存在于候选；每方至少有 1 个角色；三类角色各至少有 1 个；流程含秘密共享或混淆电路时计算方不少于 2 个，因为份额与混淆表必须分属不共谋的两方，否则单个计算方即可还原明文。输入方数决定份额的来源，计算方数决定份额份数，输出方是结果的唯一接收者。

参数（MPC-PROTO-06）。参数表 params_schema 定义每个参数的 key、类型（enum、int、bool）、范围、单位与默认值。PUT 以平台默认值为底合并并整体校验，额外约束 frac_bits 不大于 ring_bits 的一半，保证定点乘法截断前不溢出。保存的参数只影响本项目；预估、试运行、建任务在请求未带 params 时使用保存值，带 params 时使用请求值（高级模式下尚未保存的编辑）。参数直接进入代价模型：环位数 ℓ 决定份额字节数 ℓ/8，半门与 Free-XOR 开关决定每个门的密文数，k 与批大小决定 OT 的通信与轮数。

性能预估（MPC-PROTO-07）。通信量按步骤累加全体参与方发送的字节：秘密共享输入分享为 n(n − 1) × ℓ/8 × m（n 为参与方数，m 为数据行数），乘法为 2 × n(n − 1) × ℓ/8 × m × (n − 1)，混淆电路为 AND 门数 × 2κ 加输入比特数 × 3κ，OT 为 n × m × (k/8 + 16)。计算耗时按单方关键路径累加，使用原型标定的常数：本地加法 0.4 微秒、乘法 2 微秒、截断 1.5 微秒、AND 门 0.25 微秒、OT 0.6 微秒。通信耗时 = (通信量 / n) × 8 / 带宽 + 总轮数 × 往返时延。预估随参与方数与数据规模单调增长，带宽翻倍时传输时间减半。

### 3.3.2 运维监控

#### 功能说明

运维监控实时展示每个参与方的通信量、计算耗时和轮次交互数，自动检测偏离平均值的异常节点并告警，并提供历史任务的指标查询、对比与报表导出（MPC-OPS-01 至 MPC-OPS-05）。

#### 处理流程

1. 任务创建时固化性能预估结果。
2. 任务执行期间服务端每 420 毫秒产生一个心跳，共 30 个，通过 SSE 的 metrics 事件推送各方指标、汇总、进度与告警；页面按事件就地刷新，不轮询。
3. 执行满 5 个心跳后开始异常检测。
4. 任务结束后自动进入历史任务列表，可筛选、对比、导出。

#### 关键算法与参数

监控指标。第 t 个心跳时，某方通信量 = 预估总字节 / n × 进度 t/30 × 该方系数（0.94 至 1.06 之间，种子为 task_id 与 party_id）；计算耗时 = 预估计算耗时 × 进度 × 该方耗时系数；轮次交互数 = round(预估总轮数 × 进度)，结束时等于预估总轮数，所有参与方同步推进（MPC 的轮次是全体同步的消息往返）。总轮数来自预估模型：秘密共享每次打开 1 轮、乘法深度 2ceil(log₂n)，混淆电路常数 4 轮，OT 为 3 + 2ceil(m/B)，协议切换 2 轮。汇总给出 max_compute_sec 与 mean_compute_sec；前端条形宽度 = 本方 / 最大值，偏离率 = (本方 − 均值) / 均值。

异常检测。执行满 5 个心跳后，对通信量与计算耗时分别计算全部参与方的均值 μ，某方 \|x − μ\| / μ 大于阈值即标记为 abnormal，并产生 comm_anomaly 或 compute_anomaly 告警，告警含 ratio_to_mean、deviation_pct、threshold_pct、node_id，raised_at 为首次触发时间。阈值默认 50%，创建任务时可配，取值 10% 至 200%。演示环境把部分节点设为链路降级（通信乘 2.4、计算乘 2.2），3 方任务中降级节点的通信偏离约为 +60%，其余两方约为 −30%，因此只有降级节点触发告警。

历史查询与对比。每个项目播种 6 条只读历史任务（2026 年 9 月 12 日至 10 月 20 日，覆盖三种协议与 3 方、4 方），新执行完成的任务自动进入历史。列表按结束时间倒序，protocol 条件按流程中任一步使用该协议匹配，日期按 +08:00 的结束日期过滤。对比接口只允许 2 个任务，返回 8 项指标及 diff_pct = (B − A) / A，并给出每万行耗时 = 总耗时 / (行数 / 10,000) 以消除数据规模差异。报表为带 UTF-8 BOM 的 CSV，选 2 个任务时追加对比段。

| 接口 | 用途 |
|---|---|
| GET /mpc/tasks/{task_id}；GET /mpc/tasks/{task_id}/events（SSE） | 任务详情与实时事件 |
| POST /mpc/tasks/{task_id}/actions | 开始、停止、重置 |
| GET /projects/{project_id}/mpc/tasks | 历史任务列表 |
| GET /projects/{project_id}/mpc/tasks/compare | 两个任务的指标对比 |
| GET /projects/{project_id}/mpc/reports/export | 报表导出 |

已结束的任务再次 start 返回 40901；告警阈值小于 10% 或大于 200% 返回 40003；日期格式错误返回 40002，起止日期颠倒返回 40000；对比的任务数不是 2 返回 40000；任务不存在返回 40400。停止后各方指标冻结，重置后归零。

## 3.4 隐私求交模块

### 3.4.1 数据接入

#### 功能说明

数据接入登记参与求交与训练的数据集，支持数据库（JDBC）、HDFS、文件上传三种来源，平台只保存元数据与 schema；提供字段与脱敏预览；管理数据集状态并在被运行中流水线引用时禁止删除（PSI-DATA-01 至 PSI-DATA-03，对应合同 C-15）。

#### 处理流程

1. 选择参与方与来源类型，填写来源地址、求交键列、时间列等。文件来源先经 POST /files（purpose 为 dataset）上传到本参与方节点，再以 file_id 登记。
2. 提交后数据集状态为 importing，后台做连通性检查与 schema 探测，完成后变为 ready，失败为 failed。
3. 就绪后可查看字段列表与脱敏样例；未就绪的数据集不能用于求交。
4. 删除数据集前检查是否被运行中的流水线引用。

#### 关键算法与参数

登记模型。source_type 取 database、hdfs、file，source 分别保存 jdbc_url 与表名、HDFS 路径、file_id 与文件名，原始数据留在参与方节点。JDBC 地址前缀限 mysql、postgresql、oracle、hive2，HDFS 路径必须以 hdfs:// 开头，列名须匹配正则 [A-Za-z_][A-Za-z0-9_]*。

脱敏预览。详情接口在数据集视图上追加 preview：取前 3 行、前 6 列；求交键列输出哈希前缀（FNV-1a 派生的 6 位十六进制加省略号），字符串列一律输出 `***`，数值列输出 0 至 1 的归一化值，原始值不出域。状态不是 ready 时 preview 为空。feature_count 不计求交键、时间列、label 和证件哈希列，供特征对齐计算维度。

状态机。importing 到 ready 或 failed。ready 之前 row_count 为空，前端在存在 importing 数据集时每 800 毫秒轮询列表。

### 3.4.2 算法配置

#### 功能说明

算法配置提供 ECDH-PSI、KKRT（基于 OT）、非平衡 PSI 三种协议，每种协议显示各自的调优参数；支持保存与加载配置模板；并根据双方数据量与网络带宽推荐协议和参数（PSI-ALGO-01 至 PSI-ALGO-04，对应合同 C-15、C-16）。

#### 处理流程

1. 页面读取协议目录，切换协议后参数区随之切换。
2. 用户调整参数，保存为项目当前配置；或加载模板，模板内容成为当前配置。
3. 自适应路由：输入双方数据量与网络条件，服务端比较三种协议的代价并给出推荐，用户可一键采用。
4. 当前配置是平台集成页启动流水线时唯一的参数来源。

#### 关键算法与参数

协议与安全强度。协议目录返回 ecdh、kkrt、unbalanced 三项，协议键作为稳定 ID 贯穿配置、模板与流水线。每项带 security 对象，含 security_bits（128）、安全基础、详细说明与敌手模型。ECDH-PSI 基于椭圆曲线判定性 Diffie-Hellman 假设，曲线限定 Curve25519 或 NIST P-256；KKRT 由基础 OT 加 OT 扩展构成，安全参数 λ = 128，PRF 为 AES-128，统计安全 40 位；非平衡 PSI 为 ECDH-OPRF 加 BFV 同态多项式求值，环维度 8192，达到 128 位安全。

参数规格。参数规格随协议下发：type 取 enum、int、float、bool，并带 options 或 min、max、step、unit，前端据此渲染下拉框、数字框或开关并做同规则校验，后端 PUT 时再校验一次。当前配置按项目存储，记录 source（手动调整、模板或自适应路由推荐）与 updated_at。

模板。模板为 { template_id, name, protocol, params, builtin }，按项目存储，首次访问播种两个内置模板（广域网 ECDH 大分块、同机房 KKRT 默认）。保存时按协议参数规格校验并补全默认值，名称必填且不超过 40 个字。加载模板即读取模板后以 template_id 调用配置保存接口，模板协议须与当前协议一致。

自适应路由（PSI-ALGO-04）。采用解析式代价模型：在线耗时 = 计算耗时 + 通信字节 × 8 ÷ 带宽 + 往返次数 × 2 × 延迟。ECDH-PSI 通信量 (n_A + n_B) × 32 字节，计算量为 2 × (n_A + n_B) 次标量乘法；KKRT 通信量 1.27 × n_s × 64 + 3 × n_l × (40 + log₂(n_A × n_B)) ÷ 8 字节（n_s、n_l 为小集合与大集合的元素数），计算按对称运算每条 1.5 微秒；非平衡 PSI 的在线开销随小集合线性增长，大集合的离线预处理可缓存。推荐在线耗时最短的协议（相差 10% 以内时取通信量更小者），并按延迟调整 ECDH 的分块、按行数确定小集合方。典型场景表用同一模型计算 3 种规模与局域网、广域网两种网络，页面标明为估算值而非实测。例如 1 亿行对 1 万行时推荐非平衡 PSI。

### 3.4.3 平台集成

#### 功能说明

平台集成提供「安全求交、特征对齐、联合训练」的一键流水线，并跟踪各阶段的状态、时长与数据量（PSI-PIPE-01、PSI-PIPE-02，对应合同 C-15 与 T-03）。

#### 处理流程

1. 页面不再编辑参数，只读取算法配置页保存的当前配置，或所选模板的协议与参数。
2. 用户选择求交的两方、各自的数据集与求交键，提交后创建流水线。
3. 流水线依次执行三个阶段：intersect（安全求交）、align（特征对齐）、train（联合训练）。
4. 联合训练阶段按配置新建联邦学习任务，数据来源标记为该流水线；完成后页面显示写入的联邦项目与任务 ID，可跳转到过程管控定位该任务。

流水线请求。parties 恰好两方且参与方不同；每方的数据集必须属于该方且状态为 ready，求交键列必须存在于数据集的列中。联合训练阶段按 training.fl_job_config（例如 XGBoost 加同态聚合，使用项目全部节点）新建联邦任务，dataset_source 为 { type: psi_pipeline, pipeline_id }，auto_start 默认为 false，即只把对齐样本写入联邦项目，由用户在联邦模块手动启动。

阶段统计。进度经 SSE 的 stage_progress 与 pipeline_finished 事件推送，前端按 stage 键替换对应阶段并重绘。统计来自所选数据集：left_rows、right_rows 为两方的 row_count，交集条数按较小集合估算，特征维度为两方 feature_count 之和。页面显示每个阶段的状态、进度条、执行时长（秒）、数据量（求交为两方行数与交集条数，对齐为条数与特征维度）。离开页面时关闭 SSE，回来时按 pipeline_id 拉取详情；运行中则重新订阅；取消后状态为 canceled，进度归零。

## 3.5 差分隐私模块

### 3.5.1 隐私机制

#### 功能说明

隐私机制提供高斯机制与拉普拉斯机制，配置各自的核心参数，按数据分布特征自适应确定噪声尺度，并按组合定理（基础、高级、RDP）编排多维分析的隐私强度并下发到任务（DP-MECH-01 至 DP-MECH-04，对应合同 C-07、C-08）。

#### 处理流程

1. 页面读取机制目录，展示两种机制的定义、噪声分布、定标公式和适用场景；当前任务在用的机制有标识。
2. 为训练任务配置参数：总预算 ε、裁剪阈值 C、δ、会计方式；或为统计查询配置字段范围与预算并发布加噪结果。
3. 自适应噪声：输入字段分布特征，系统给出固定裁剪与自适应裁剪的对比与推荐。
4. 策略编排：为多个维度设定总预算与权重，选择组合方式，系统分配各维度预算并下发到任务。

#### 关键算法与参数

机制。高斯机制满足 (ε, δ)-DP，标准差 σ = Δ₂ × √(2 ln(1.25/δ)) / ε，Δ₂ 为 L2 敏感度，用于梯度扰动并可配 RDP 会计；拉普拉斯机制满足纯 ε-DP（δ = 0），尺度 b = Δ₁ / ε，Δ₁ 为 L1 敏感度，用于低维统计查询。训练引擎与统计查询共用这两种机制。

任务参数。梯度对象的参数存于任务的 dp 配置：总预算 epsilon_total 取 0.2 至 10，裁剪阈值 clip_norm 取 0.2 至 4，delta 取 1e-4、1e-5 或 1e-6，accountant 取 basic、advanced 或 rdp，默认为 rdp（显式指定 basic 时数值与基础组合一致），另有 clip_mode。统计查询对象存为项目级配置，发布时按字段分布确定敏感度后加噪，结果裁回裁剪区间（后处理不消耗预算）。

自适应噪声（DP-MECH-03）。字段按对数正态拟合（中位数、对数标准差），敏感度 Δ = (U − L) / n，U、L 为裁剪上下界，n 为样本数。固定裁剪使用业务公开的取值范围，不看数据；自适应裁剪在 P1 至 P99、P2.5 至 P97.5、P5 至 P95、P10 至 P90 四个分位区间中，按 RMSE = √(噪声方差 + 截断偏差²) 最小者选取，截断偏差用对数正态截断期望解析计算，其中 10% 的预算用于差分隐私分位数估计。对重尾字段（例如 CeO₂ 月度均价），自适应裁剪使噪声标准差降低约 84%；对样本量大的全量均值，固定裁剪更优，系统据此给出推荐。梯度侧按 Andrew 等（2021）的目标分位裁剪：每轮的 C 取上一轮参与方更新 L2 范数的中位数，噪声 σ = z × C（z 为噪声倍数）随之下降，裁剪比例稳定在 50% 附近。

组合定理（DP-MECH-04）。设单步预算为 ε₀，共 T 步。基础组合：ε = T × ε₀。高级组合（Dwork、Rothblum、Vadhan）：ε = ε₀ × √(2T ln(1/δ′)) + T × ε₀ × (e^ε₀ − 1)，δ = T × δ + δ′；当高级组合劣于基础组合时取基础组合。RDP（Mironov 2017）：高斯机制单步 ε(α) = α / (2z²)，拉普拉斯机制用闭式 RDP，T 步后 ε = min over α 的 [T × ε(α) + ln(1/δ) / (α − 1)]，α 取 22 档。作为对照，同样 30 轮、ε₀ = 0.0667 时累计 ε 分别为：基础 2.00，高级 1.89，RDP 0.37。策略在维度之间按顺序组合：ε_i = ε_总 × w_i / Σw；维度内按所选会计方式用二分法反解噪声倍数。下发时先整体校验，再写入任务 dp 配置的 epsilon_total、clip_norm、accountant 与 policy_id。

### 3.5.2 效果评估

#### 功能说明

效果评估在训练过程中实时计算已消耗的隐私预算与模型效用，给出效用与隐私预算的趋势曲线和平衡点分析，并保留每轮的隐私审计记录（DP-EVAL-01 至 DP-EVAL-03，对应合同 C-09）。

#### 处理流程

1. 页面选择任务，显示 DP 配置、已消耗 ε、占比、已完成轮次、模型效用与无噪声基线。
2. 趋势曲线与平衡分析调用估算与权衡接口。
3. 审计记录按轮次列出每轮的 ε 增量、噪声尺度等，可导出 CSV。

#### 关键算法与参数

预算累计。已消耗 ε 按任务的会计方式对已完成轮次累计：basic 为 ε_总 × r / T，advanced 与 rdp 按 3.5.1 的公式累计；used_pct = ε_used / ε_总。训练运行期间配置存快照，训练结束后改配置不影响该次运行的预算。RDP 会计下跑满 T 轮恰好用完总预算。

模型效用。效用公式中的 ε 取与当前噪声等效的基础组合总 ε，因此 RDP 下同样的总预算对应更小的噪声、更高的效用。界面以百分比显示效用，并给出无噪声基线与损失的百分点。

平衡点。对 ε 网格 0.2 至 10 逐点，按同一机制、C、δ、会计方式反解噪声并估算效用；recommended_epsilon 取效用损失不超过 max_accuracy_loss（默认 0.03，即 3 个百分点）的最小 ε，并说明当前 ε 在平衡点的哪一侧。效用随 ε 单调不降；RDP 达到同样效用所需的 ε 明显小于基础组合。

审计记录。训练引擎每轮聚合后写入审计，按该次运行的配置快照补齐：ε 增量 = 累计 ε(r) − 累计 ε(r − 1)、噪声尺度、自适应 C、裁剪比例与噪声 L2 范数。因此逐轮增量之和等于累计 ε。已完成的历史任务可看到全部轮次，播种的历史任务按其配置回放，标记 source 为 seed_history。limit 参数支持整数与 all；CSV 带 UTF-8 BOM，列与页面一致。

### 3.5.3 框架集成

#### 功能说明

框架集成把差分隐私接入联邦训练引擎：基于隐语原生 DP 模块封装并保留可替换性，任务启用 DP 时在梯度聚合前自动调用，提供框架内部的 DP 指标，并把「配置、初始化、裁剪加噪、聚合、预算记账」串成端到端工作流（DP-FW-01 至 DP-FW-04，对应合同 C-10 与 T-03）。

#### 处理流程

1. 配置：为任务设定 DP 机制与预算（或下发策略）。
2. 初始化检查：对 7 个前置条件逐项校验，全部通过才能进入启动。
3. 启动：训练引擎初始化 DP 策略对象。
4. 每轮在梯度聚合前依次执行裁剪、加噪，聚合后记账。
5. 预算与审计在效果评估页查看，与框架集成页显示同一任务。

#### 关键算法与参数

统一接口与可替换实现（DP-FW-01）。平台只依赖 5 个统一接口：DPStrategy.build、GradientDP.gaussian、GradientDP.laplace、Accountant.spent、SecureAggregator.aggregate。三种实现 secretflow-native、opacus、tf-privacy 暴露同一组接口。隐语侧映射 secretflow.security.privacy.DPStrategyFL、secretflow.security.privacy.mechanism.tensorflow.GaussianModelDP、secretflow.security.aggregation.SecureAggregator，类路径以部署环境的隐语版本为准；隐语没有的联邦拉普拉斯机制和三种会计方式由适配层 dp_adapter 实现。切换实现只影响非运行任务，运行中的任务沿用原实现到本次训练结束。

初始化与调用顺序（DP-FW-02）。任务 start 时，若 dp_enabled 且任务 dp 配置启用，训练引擎按当前实现初始化 DP 策略对象，并在每轮梯度聚合前依次调用裁剪、加噪与记账。各参与方加噪声 N(0, σ²/n)，聚合后总噪声为 N(0, σ²)。因此裁剪与加噪的调用次数等于轮数 × 参与方数，聚合与记账的调用次数等于轮数；未启用 DP 的任务跳过这三步。

框架内部指标（DP-FW-03）。裁剪比例 = P(‖g‖₂ > C)，样本梯度范数按对数正态建模，中位数随轮次衰减；噪声 L2 范数在高斯机制下为 σ√d，拉普拉斯机制下为 b√(2d)，d 为模型参数维度（原型中各算法统一取值：逻辑回归 69，XGBoost 每轮上传的直方图 2,176，CNN 61,706，LSTM 203,143，TCN 37,959）；信噪比 = n × B × E[min(‖g‖₂, C)] / ‖噪声‖₂，其中 B 为每参与方每轮 256 个样本（按逐样本裁剪的 DP-SGD，信号取上界），分贝值 = 10 × log₁₀(信噪比²)。噪声分布直方图对末轮噪声坐标抽样 4000 个（种子为任务 ID 加轮次，结果稳定），同时返回理论密度用于对照。

端到端工作流（DP-FW-04）。向导把 DP 配置、初始化检查、训练启动与预算记账串成固定五步：配置写入任务 dp 配置，init-check 校验 7 个前置条件，启动后训练引擎在聚合前调用 DP 钩子，预算按任务会计方式逐轮累计。第 5 步与效果评估页显示同一任务的已消耗 ε；已完成的任务在第 3 步提示需先重置。

# 6 接口设计总述

## 6.1 基础约定与统一响应包

| 项 | 约定 |
|---|---|
| 基础地址 | https://{host}/api/v1，协议为 HTTPS |
| 请求体 | application/json，UTF-8；文件上传用 multipart/form-data |
| 字段命名 | snake_case |
| 时间 | ISO 8601，带时区，例如 2026-09-18T16:42:00+08:00 |
| 时长与数据量 | 单位写在字段名里：_ms 毫秒、_sec 秒、_bytes 字节、_kb KB |
| 数值格式化 | 后端返回原始数值，前端负责格式化 |
| ID | 字符串，由后端生成 |

所有 JSON 接口返回统一响应包，由 code、message、data、request_id 四个字段组成。code 为 0 表示成功；失败时 code 为非 0 业务码，data 为空或带出错上下文（例如出错字段名、允许的动作）。HTTP 状态码与业务码同时生效。文件下载接口直接返回文件流，不走响应包。

```json
{ "code": 0, "message": "ok", "data": { }, "request_id": "req_8f3a2c1d" }
```

## 6.3 鉴权

除登录外，所有接口需带请求头 Authorization: Bearer {access_token}。未登录或 token 失效返回 HTTP 401、业务码 40100。浏览器 EventSource 无法设置请求头时，SSE 端点接受 access_token 查询参数。挂在项目下的资源使用 /projects/{project_id}/… 路径；已有 ID 的资源（任务、评估、流水线）直接用 /fl/jobs/{job_id} 一类路径，由后端校验该资源属于用户可访问的项目，否则返回 40300。

## 6.4 分页

列表接口统一使用 page（从 1 开始，默认 1）与 page_size（默认 20，最大 100）。分页响应的 data 为 items、page、page_size、total 四个字段。

## 6.5 实时推送（SSE）

# 7 安全设计

## 7.1 数据不出域

原始数据只存在于参与方节点的本地数据目录。平台只登记数据集的元数据与 schema，文件来源的数据先上传到本参与方节点，再以 file_id 登记。训练节点的数据目录权限为 0700，并通过挂载命名空间隔离，只有目录属主节点能访问。节点间通信限定为 ModelUpdate 消息的白名单字段（训练节点上传 weights_delta、num_samples、local_metrics，聚合节点下发 global_weights 与 round），不包含样本、标签或特征。传输审计把最后一轮的消息字段名与本项目所有数据集的列名比对，命中 0 个才判为通过。数据集预览对求交键只显示哈希前缀、字符串列打码、数值列归一化，原始值不出域。

梯度本身也可能泄露样本，因此上传前还要经过多层处理：差分隐私裁剪与加噪、Top-k 稀疏与量化、秘密共享掩码或同态加密。聚合节点只接触份额或密文。梯度重构攻击评估（见 4.17）用来衡量这些措施叠加后的残余风险。

## 7.2 密钥管理

私钥由平台 KMS 托管，不出域；平台与接口只保存 private_key_ref（kms:// 引用）与 key_id，任何接口都不返回私钥材料。公钥带 SHA-256 指纹，可查看。密钥全生命周期受管：生成、分发到节点、存储、轮换、销毁。轮换时旧密钥只用于解密历史密文，不能再加密新数据（40901）；销毁时同时删除密钥与其下密文，并保留销毁记录；会话密钥 24 小时过期，不参与轮换；聚合密钥可按项目配置的周期（1 至 365 天）自动轮换。聚合页与同态加密页共用同一张密钥表，避免任务使用与配置不一致的密钥；同态参数与有效密钥不一致时拒绝保存配置。

## 7.3 传输与存储

控制台与后端之间使用 HTTPS 与 Bearer token。参与方节点与聚合节点之间的通信通道加密由所选联邦学习框架提供，部署时按框架的 TLS 配置启用。配置导出文件（schema_version 为 fl-project-config/1）包含项目、训练配置、节点清单与隔离策略，不含凭据与私钥。元数据存放在元数据库，模型与数据集制品存放在制品存储；数据集制品只存在于所属参与方节点。接口响应中涉及的敏感值只给出引用或指纹。

## 7.4 审计

平台记录以下审计信息：越权访问判定结果与操作人（fl_isolation_audit）；算法发布与回滚的操作人、原因、时间（fl_algorithm_op_log）；项目配置变更的 revision、修改人与时间；任务状态迁移历史（state_history，含终止原因）；每轮差分隐私预算消耗与噪声详情（dp_audit，可导出）；同态加密各环节的耗时与密文大小日志；密钥的分发、轮换、销毁记录。任务控制动作接受 reason 字段，终止时建议填写，写入审计日志。

| 契约测试 | 对 mock 后端的每个接口验证正常路径与校验失败路径，覆盖错误码、边界值、状态机与确定性结果；同一套测试可指向真实服务端复用 | Node 自带 node:test，web/tests/*.test.mjs |
| 浏览器验收 | 在控制台页面按功能块的 data-acc 标记定位，按操作步骤核对预期现象，并检查页面无报错提示与 console 错误、换项目后正常 | 浏览器自动化会话，截图归档 |
| 验收进度表 | 汇总每个三级功能的实现状态、单元测试结果、浏览器验收结果，生成 HTML、JSON 与 Excel | tools/acceptance.py，输出到 dist/acceptance |
| 指标验证 | 在验收环境重跑 T-01、T-02 评估，并对加密、求交、安全计算做性能测试 | 见第 10 章 |

## 8.2 用例与编号对应

每个三级功能至少有一个测试，测试名以功能编号开头，一个测试可以覆盖多个编号，例如 [FL-ORCH-01][FL-ORCH-04]。测试文件与模块对应如下。

| 测试文件 | 覆盖内容 |

| fed-proc.test.mjs | FL-PROC-01 至 FL-PROC-08：状态机、启动预检、断点、终止、指标、ETA、导出 |
| fed-sec.test.mjs | FL-AGG-01 至 FL-AGG-07、FL-EVAL-01 至 FL-EVAL-03：聚合参数校验、密钥、估算、评估 |
| he.test.mjs | HE-ALGO-01 至 HE-ALGO-08、HE-APP-01 至 HE-APP-05 |
| mpc.test.mjs | MPC-PROTO-01 至 MPC-PROTO-07、MPC-OPS-01 至 MPC-OPS-05 |
| psi.test.mjs | PSI-DATA-01 至 PSI-DATA-03、PSI-ALGO-01 至 PSI-ALGO-04、PSI-PIPE-01、PSI-PIPE-02 |

运行命令如下，需要 Node 20 及以上版本。

```
cd web
node --test tests/*.test.mjs
```

三级功能的完成判据为：开发者标记 done，且该编号的全部单元测试通过，且浏览器验收通过；缺其中任何一项记为未完成。当前的测试数量与通过情况以验收进度表为准，本文不另写数字。

## 8.3 合同测试项的验证对应

合同条目与测试的对应关系见第 4 章每一项的「验证方法」。T-01、T-02 当前数值来自原型内置评估引擎的仿真结果，契约测试验证的是接口结构、判定口径、可复现性与校验规则；验收环境中以评估引擎的实际运行结果为准。

# 9 部署与运维

## 9.1 部署

控制台是静态站点，无构建步骤，任何静态服务器都可以托管，例如在 web 目录下运行 python3 -m http.server 8412 --bind 127.0.0.1，或把 web 目录设为 nginx 的站点根目录。接入真实后端时修改 web/js/config.js 两项：apiBase 设为后端地址，useMock 设为 false，另需配置 accessToken。

后端部署为服务端 1 台加参与方节点 3 个：服务端运行平台后端、聚合节点、评估引擎和元数据库；每个参与方节点运行训练进程或容器，并准备独立的本地数据目录。训练任务启动时由服务端为每个节点分配训练进程或容器，终止时释放。容器编排与端口规划在部署实施时细化。

## 9.2 运维

- 监控：联邦任务在过程管控页实时查看状态、轮次、指标与剩余时间；多方安全计算任务在运维监控页查看各方通信量、计算耗时、轮次与异常告警。
- 日志：同态加密各环节耗时与密文大小写入性能日志，可导出；训练任务的状态迁移与差分隐私审计可导出。
- 数据保护：元数据库与密钥元数据需要定期备份；私钥在 KMS 中，由 KMS 自身的备份策略负责。
- 变更：算法与模型以版本管理，回滚只移动当前版本指针；项目配置变更带 revision，可追溯。
- 验收辅助：tools/acceptance.py 重新生成验收进度表，随版本一并交付。

# 10 风险与后续计划

## 10.1 风险与限制

| 风险或限制 | 影响 | 应对 |
|---|---|---|
| T-01、T-02 的数值来自原型内置评估引擎的仿真结果 | 当前数值是仿真值 | 验收环境中由评估引擎实际运行 DLG、iDLG 攻击与联邦训练，按同一结构返回结果并重跑 |
| CIFAR-10 对联邦轮次敏感 | 评估引擎文档指出联邦轮次取 10 时下降约 4.2 个百分点，未达到不超过 3 个百分点 | 验收使用默认 50 轮联邦轮次；必要时调整稀疏化比例或噪声预算 |
| 同态、安全计算、求交的耗时与通信量为模型估算 | 与实测值可能有偏差 | 页面标明为估算值；验收环境实测后校准估算常数 |
